一、Veritas 是什么

Veritas 是一台抽象机器（Abstract Machine）。

它不是数据库，不是编程语言，不是框架，不是操作系统内核。
它是一台用软件定义的虚拟计算机，运行在现有 CPU 和操作系统之上，
为运行在它上面的程序提供一套全新的、带有确定性保证的运行时环境。

它在技术栈中的位置：

应用程序 / DSL / AI Agent / 业务模块
----------------------------------
      Veritas Abstract Machine      <- 我们在这里
----------------------------------
      Rust（宿主语言）
----------------------------------
      Linux / Android / Windows
----------------------------------
      CPU (x86 / ARM)


二、和 JVM 的类比

JVM 做的事情：
- 定义了一套字节码指令集（iload / istore / invokevirtual / new）
- Java 编译器把 Java 代码编译成字节码
- JVM 执行字节码，把它翻译成真正的 CPU 指令
- 程序员只需要面向 JVM 编程，不需要关心底层是 x86 还是 ARM

Veritas 做的事情类似，但目标不同：
- JVM 承诺的是跨平台执行
- Veritas 承诺的是行为正确性

Veritas 的指令集不是字节码，而是：
BEGIN / READ / WRITE / COMMIT / ABORT
SAVEPOINT / ROLLBACK_TO
EFFECT
ENUM_SCOPE / BIND_TO_SCOPE / UNBIND_FROM_SCOPE
GRANT / REVOKE / DELEGATE / HOLD_CHECK
REQUIRE / ENSURE / INVARIANT

这些指令最终由 Rust 实现，但在 Veritas 的世界里，它们是机器指令。


三、为什么需要 Veritas

现代软件中，以下问题完全依赖程序员自觉：
- 改了一个函数，怎么知道不会搞崩别的地方？
- 两个并发请求同时修改同一行数据，怎么保证不丢更新？
- 程序崩溃在中间状态，重启后怎么恢复到一致状态？
- 一个模块调用另一个模块，怎么保证调用方有权限？
- 发出去的邮件/短信/HTTP请求，如果事务失败怎么撤回？

对于这些问题：
- CPU 完全不知道（它只知道 Load/Store/Add/Jump）
- 操作系统完全不知道
- 编程语言也完全不知道

Veritas 说：把这些保证，从程序员的手里，交到机器的手里。
- 程序员不需要记得先检查再修改——机器强制执行
- 程序员不需要手动处理并发冲突——机器自动检测
- 程序员不需要自己写崩溃恢复——WAL 自动重放
- 程序员不需要担心副作用撤回——EFFECT 暂存到 COMMIT 后才执行


四、Veritas 的核心承诺

Veritas 对运行在它上面的所有程序做出以下不可动摇的保证：

1. 状态修改必须在事务内进行。没有例外。
2. 并发事务自动冲突检测。读写冲突和幻读冲突都会被拦截。
3. 提交成功的数据不会丢失。WAL 保证崩溃恢复。
4. 能力凭证不可伪造。没有授权的模块碰不到受保护的数据。
5. 副作用在提交后才执行。ABORT 的事务不会产生任何外部影响。

这些承诺不是编程规范，不是代码审查的要求，而是机器的物理定律。
任何程序，无论怎么写，都无法绕过它们。


五、Veritas 不是什么

- 不是数据库：不提供 SQL、表、索引、查询优化器。Veritas 是更底层的事务抽象机。
- 不是编程语言：不定义语法、不提供类型系统。Veritas 是执行层，语言可以编译到它上面。
- 不是操作系统：不管理进程、文件系统、网络栈。Veritas 运行在操作系统之上。
- 不是区块链：不涉及共识协议、P2P 网络、代币经济。Veritas 是单机抽象机。
- 不是 LLVM：LLVM 是编译器中间表示，目标是生成高效机器码。Veritas 是运行时，目标是行为保证。

七、设计哲学

原则一：保证优先于性能。
慢但正确，优于快但有漏洞。

原则二：原语最小化。
每条原语必须通过删除测试：删除它，是否有某条机器保证无法实现？

原则三：不可绕过优先于便利性。
显式声明优于隐式推断。机器只保护程序员显式声明的东西。
机器世界里没有警告，只有允许和拒绝。

Veritas 是一台不信任程序员的抽象机器。
它把行为正确性从编程规范变成机器保证。
